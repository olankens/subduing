## FEATURES

<table>
  <tbody><tr><td width="99999">Enforce conventional commit types including feat, fix, docs, style, refactor, perf, test, build, ci, chore, and revert across every Git software repository message header automatically.</td><td>✅</td></tr></tbody>
  <tbody><tr><td width="99999">Verify each commit subject starts using a proper English verb by consulting online dictionary services and rejecting messages that begin with invalid words during the entire review process.</td><td>✅</td></tr></tbody>
  <tbody><tr><td width="99999">Reject commit messages containing body text beyond the first line, ensuring all Git history entries remain concise single-line descriptions without additional paragraphs or multi-line content.</td><td>✅</td></tr></tbody>
  <tbody><tr><td width="99999">Prevent commit footers from appearing in messages by parsing trailer information and blocking any Git commits that include metadata sections placed after blank lines during validation checks.</td><td>✅</td></tr></tbody>
  <tbody><tr><td width="99999">Validate commit header length stays between sixty-five through seventy characters, maintaining readable Git log output while providing sufficient detail for clarity plus overall consistency.</td><td>✅</td></tr></tbody>
  <tbody><tr><td width="99999">Ensure all commit header text uses lowercase letters only, catching accidental capitalization that breaks the uniform appearance of project version history records and reduces visual noise.</td><td>✅</td></tr></tbody>
  <tbody><tr><td width="99999">Block commit headers that end with punctuation symbols like periods, question marks, exclamation points, or commas to keep messages clean and consistent across all software project teams.</td><td>✅</td></tr></tbody>
  <tbody><tr><td width="99999">Detect unusual characters inside commit headers including square brackets, at symbols, hashes, dollar signs, percent marks, ampersands, asterisks, braces, pipes, plus tildes, and backslashes.</td><td>✅</td></tr></tbody>
</table>
